## Defects found by this stage

1. **`export --format env` corrupted multiline secrets.** A PEM-shaped value was
   written raw, so its remaining lines became bogus variables
   (`MIIBcanaryline1=<0 bytes>`, `-----END EXAMPLE KEY-----=<0 bytes>`) and the
   file was silently invalid. Now the command refuses multiline values, names
   them, and writes nothing. `--format json` remains lossless for them.
2. **`export --prefix` used a string prefix.** `--prefix app/ci` also exported
   `app/ci-tokens/*`. Now segment-aware (`name == prefix or prefix + "/"`),
   matching the policy engine.
3. **Variable collisions were silent.** `app/ci/token` and `app/ci-token` both
   render `APP_CI_TOKEN`; the later value silently won. Now refused.
4. **Wrong invocation for in-image helpers.** `docker run IMAGE python -c …` is
   swallowed by the entrypoint (`unrecognized arguments`); `--entrypoint python`
   is required. Same root cause as the Stage 3 `--generate-key` fix.

Five CLI tests were added (`tests/test_cli.py`), six assertions were added to
`tests/smoke.sh`, and the unit suite is now 40 tests (1 skipped on Windows: NTFS
cannot express `0600`, which the container check covers).

## Limitations

- Verification ran on a Windows host over loopback; timings include Docker
  Desktop's NAT and are not representative of the OCI instance.
- The service speaks plain HTTP on loopback. TLS termination and network
  restriction are Stage 5 concerns; do not expose port 8200 publicly.
- Concurrency was exercised at 10 parallel clients on a 1 GiB-class envelope,
  not a sustained multi-process load test.
- No cloud resources were created; `tofu apply` remains Stage 5.
