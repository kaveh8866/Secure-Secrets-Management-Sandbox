6. Defects found and fixed during this stage
   a) outputs.tf used ${var.api_port} inside an output `description`. Terraform
      forbids variables there: "Variables may not be used here." Reworded.
   b) modules/network had no versions.tf, so `providers = { oci = oci }` failed
      with "Reference to undefined provider". Added the required_providers block.
   c) vcn_dns_label was "cloudguardsecrets" (17 chars); the validation rule
      rejected it at 15. Renamed to "cgsecrets".
   d) The cloud-init template contained "PermitiRootLogin" (typo). Fixed to
      PermitRootLogin before any apply could ship a broken sshd drop-in.

7. What was NOT done
   * No `tofu apply`. Provisioning is Stage 5; this stage only proves the
     configuration is valid and the plan matches the intended six resources.
   * No provider-side verification (nothing exists to verify).
   * terraform.tfvars is local and gitignored; its values were copied from the
     Project 05 operator file without being printed.

8. Portability
   Module interfaces are provider-neutral (network exposes subnet_id and
   ingress_ports; compute consumes subnet_id and returns public_ip). AWS and GCP
   mappings are documented in terraform/README.md and in file headers; OCI is the
   only validated target.
